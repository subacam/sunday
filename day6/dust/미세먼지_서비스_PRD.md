## 1. 개요 (Overview)

사용자가 대한민국 지도 또는 목록에서 **시/도 단위의 "도시 칩"** 을 클릭하면, 해당 지역의 **실시간 미세먼지(PM10) / 초미세먼지(PM2.5) 농도와 등급**, 그리고 **시간별·일별 추이 그래프**를 보여주는 웹 서비스.

데이터는 **공공데이터포털의 한국환경공단 에어코리아(AirKorea) "대기오염정보 조회 서비스" API**를 사용한다.

## 2. 배경 및 문제 정의 (Problem Statement)

- 사용자는 외출/운동/환기 여부를 결정할 때 미세먼지 정보를 자주 확인하지만, 기존 앱/사이트는 정보가 복잡하거나 지역 탐색이 번거로움.
- "도시 칩을 클릭"하는 직관적인 UX로 원하는 지역의 대기질 정보를 빠르게 확인할 수 있게 한다.

## 3. 목표 (Goals) / 목표가 아닌 것 (Non-goals)

**Goals**
- 17개 시/도의 실시간 미세먼지 상태를 3초 이내에 확인 가능하게 한다.
- 시간별(24시간) / 일별(최근 7~30일) 추이를 그래프로 시각화한다.
- 반응형 웹으로 모바일 브라우저에서도 자연스럽게 동작한다.

**Non-goals (이번 버전 제외)**
- 시/군/구 세분화 (v2 이후 확장 검토)
- 즐겨찾기, 알림/푸시 기능
- 회원가입/로그인
- 네이티브 앱 개발

## 4. 대상 사용자 (Target Users)

- 미세먼지에 민감한 일반 사용자 (호흡기 질환자, 어린이/노약자 보호자)
- 외출·운동 계획을 세우는 일반 사용자
- 빠르고 직관적인 UI를 선호하는 모바일 웹 사용자

## 5. 핵심 사용자 시나리오 (User Flow)

1. 사용자가 서비스에 접속하면 전국 17개 시/도 칩(버튼) 목록이 보인다.
2. 사용자가 특정 도시(예: "서울") 칩을 클릭한다.
3. 해당 지역의 **현재 PM10 / PM2.5 농도, 등급(좋음/보통/나쁨/매우나쁨), 측정 시각**이 카드 형태로 표시된다.
4. 하단에는 **최근 24시간 시간별 추이 그래프**와 **최근 7일 일별 추이 그래프**(탭 전환)가 표시된다.
5. 사용자는 다른 도시 칩을 클릭해 지역을 손쉽게 전환할 수 있다 (선택된 칩은 하이라이트).

## 6. 핵심 기능 (Feature Requirements)

### 6.1 도시 칩 목록
- 전국 17개 시/도(서울, 부산, 대구, 인천, 광주, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 전남, 경북, 경남, 제주) 칩을 표시.
- 클릭 시 선택 상태 UI(강조 색상) 반영.
- **위치 기반 자동 지역 감지 (v1 포함)**: 최초 진입 시 브라우저 Geolocation API로 사용자 위치를 요청하고, 위치 권한을 허용하면 가장 가까운 시/도를 자동 선택하여 해당 지역의 대기질 정보를 바로 표시한다. 위치 권한을 거부하거나 위치 조회에 실패하면 기본값으로 "서울"을 선택한다.

### 6.2 실시간 대기질 카드
- 표시 항목: PM10 농도(㎍/㎥), PM2.5 농도(㎍/㎥), 통합대기환경지수(CAI) 등급, 측정소명, 측정 시각.
- 등급별 색상 코드 적용 (좋음: 파랑, 보통: 초록, 나쁨: 주황, 매우나쁨: 빨강 — 에어코리아 기준 준용).
- 데이터 로딩 실패 시 에러 상태 UI(재시도 버튼) 노출.

### 6.3 추이 그래프
- **시간별 그래프**: 최근 24시간 PM10/PM2.5 라인 차트.
- **일별 그래프**: 최근 7~30일 일평균 PM10/PM2.5 라인/바 차트 (기간 토글 가능).
- 그래프 위에 등급 기준선(주의보 수준 등) 참고선 표시(선택 사항).

### 6.4 데이터 갱신
- 실시간 카드: 페이지 진입 시 및 도시 전환 시 API 호출 (에어코리아는 시간 단위 갱신 기준이므로 자동 폴링은 불필요, 수동 새로고침 버튼 제공 검토).

## 7. 데이터 소스 (Data Source)

- **공공데이터포털**: 한국환경공단 에어코리아 **"대기오염정보 조회 서비스"** (ArpltnInforInqireSvc)
  - 시/도별 실시간 측정정보: `getCtprvnRltmMesureDnsty`
  - 측정소별 실시간 정보: `getMsrstnAcctoRltmMesureDnsty`
  - 통합대기환경지수 등급: 각 API 응답의 `khaiGrade`, `pm10Grade`, `pm25Grade` 필드 활용
- 인증: 공공데이터포털 발급 서비스키(Encoding/Decoding 키) 필요 → 서버 사이드(백엔드/서버리스 함수)에서 호출해 키 노출 방지 권장.
- 시/도별 데이터는 각 시/도의 **대표 측정소 1곳의 값**을 사용 (예: 측정소별 실시간 정보 API `getMsrstnAcctoRltmMesureDnsty`를 대표 측정소명으로 호출). 17개 시/도별 대표 측정소 매핑 테이블은 별도로 확정 필요 (Open Question 참조).

## 8. 화면 구성 (Screens)

1. **메인 화면**: 도시 칩 목록 + 선택된 도시의 실시간 카드 + 그래프 (단일 화면, 스크롤 방식)
2. (선택) **정보/기준 안내 화면**: 등급 기준(좋음/보통/나쁨/매우나쁨 수치 기준) 설명

## 9. 비기능 요구사항 (Non-functional Requirements)

- **성능**: 도시 칩 클릭 후 데이터 표시까지 2초 이내 (API 응답 지연 고려)
- **반응형**: 모바일(360px~) ~ 데스크톱까지 대응
- **접근성**: 등급 색상 외 텍스트 라벨 병행 표기(색맹 사용자 고려)
- **에러 처리**: 공공데이터포털 API 장애/트래픽 초과 대비 캐싱 또는 재시도 로직

## 10. 성공 지표 (Success Metrics)

- 도시 칩 클릭 → 정보 확인까지 완료하는 세션 비율
- 평균 세션 내 도시 전환 횟수 (여러 지역 비교 사용 여부)
- 페이지 로드/응답 실패율

## 11. 기술 스택 (Tech Stack)

| 영역 | 선택 |
|---|---|
| 프론트엔드 프레임워크 | React |
| 차트 라이브러리 | **Recharts** — React 컴포넌트 기반으로 선언적 작성 가능, 시간별/일별 라인 차트에 적합, 반응형·툴팁 기본 지원 |
| API 연동 | 공공데이터포털 에어코리아 API — **Next.js API Route**를 서버 사이드 프록시로 사용하여 서비스키 노출 방지 및 배포(Vercel 등) 단순화 |
| 캐싱 | 서버(API Route)에서 **1시간(60분) TTL 캐싱** — 에어코리아 실시간 데이터는 매시 정각 기준 갱신되므로 이에 맞춰 캐싱, 공공데이터포털 일일 트래픽 제한(기본 1,000회) 내 여유 확보 |
| 지역 대표값 | 각 시/도별 **대표 측정소 1곳의 값을 사용** (예: 경기도 → 수원 측정소 등 지역 대표 측정소 사전 매핑 테이블 구성) |
