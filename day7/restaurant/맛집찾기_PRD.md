# PRD: 시티투어 주변 맛집 검색 서비스

## 0. 문서 정보
- 작성일: 2026-08-19
- 버전: v1.0 (Swagger 스펙 확정 반영)
- 참고 API: **"전국 시티투어 코스와 함께하는 맛집 정보"** (문화공공데이터광장/한국문화정보원, `api.kcisa.kr`, API_CNV_063)

### ⚠️ 핵심 주의사항 (기획에 영향을 주는 사실)
이 API는 전국 모든 식당을 다루는 범용 맛집 DB가 아니라, **각 지자체 시티투어 코스 주변에 위치한 식당 정보**를 제공하는 API입니다. 응답에 시티투어명(`title`), 시티투어 운행정보(`description`), 시티투어 담당 시군구(`spatial`) 등이 식당 정보와 함께 내려오는 구조가 이를 뒷받침합니다.

- 특정 지역에 시티투어 코스가 없으면 검색 결과가 없거나 매우 적을 수 있습니다.
- "우리 동네 맛집 찾기"보다는 **"여행 중 시티투어 코스 주변 맛집 찾기"**로 서비스 포지셔닝을 조정하는 것을 권장합니다.
- 서비스 기획 확정 전, 실제 서비스키로 주요 지역(서울/부산/제주 등) 테스트 호출을 해 데이터 밀도(건수)를 반드시 확인해야 합니다.
- **전화번호 필드가 없습니다.** 응답에 상호명·주소·좌표는 있지만 연락처 정보는 제공되지 않습니다.

## 1. 개요 (Overview)

### 1.1 배경
사용자가 지역(시/도 또는 시/군/구)과 음식 카테고리를 선택하면, 문화공공데이터광장의 "전국 시티투어 코스와 함께하는 맛집 정보" API를 통해 해당 조건에 맞는 시티투어 주변 식당 목록을 조회하여 보여주는 웹사이트를 구축한다.

### 1.2 목표
- 시티투어를 계획 중인 여행객이 코스 주변 맛집을 몇 번의 클릭으로 찾을 수 있게 한다.
- MVP는 "조회 및 목록 표시"에 집중하고, 이후 지도 표시·시티투어 코스 연계 정보 등으로 확장한다.

### 1.3 타겟 사용자
- 특정 지역 시티투어를 계획 중이며 주변 식당을 미리 알아보고 싶은 여행객
- 지역 출장/여행 전 시티투어 연계 맛집을 조사하는 사용자

---

## 2. 범위 (Scope)

### 2.1 MVP 범위 (In Scope)
1. 지역 선택 (시/도 드롭다운, 필요시 시/군/구까지)
2. 음식 카테고리 선택 — **API가 지원하는 8종 고정값만 사용**: 한식 / 분식 / 치킨 / 동양식 / 서양식 / 패스트푸드 / 뷔페 / 퓨전
3. "검색" 버튼 클릭 시 API 호출 → 식당 목록 표시
4. 목록 항목: 식당명, 도로명 주소, 음식 분류, 연계 시티투어명
5. 페이지네이션 또는 "더보기" 처리 (`numOfRows`/`pageNo`/`totalCount` 활용)
6. 로딩 상태 / 결과 없음 / 에러 상태 UI
7. 결과 없음 상태에는 "이 지역엔 등록된 시티투어 연계 맛집이 없어요" 등 API 특성을 반영한 안내 문구 포함

### 2.2 향후 확장 (Out of Scope for MVP)
- 지도 기반 시각화 (좌표 필드 `rstrLatPos`/`rstrLotPos` 활용, 카카오맵/네이버지도 연동)
- 연계된 시티투어 코스 상세 정보 표시 (운행정보 `description`, 홈페이지 `source` 등 활용)
- 식당 상세 페이지, 사용자 즐겨찾기 / 로그인
- 검색어(상호명) 자유 검색
- 전화번호 등 미제공 정보의 외부 데이터(카카오맵 등) 보완 연계

## 3. 사용자 시나리오 (User Flow)

1. 사용자가 사이트에 접속한다.
2. 지역을 선택한다. (예: 서울, 또는 강남구처럼 시/군/구 단위)
3. 음식 카테고리를 8종 중에서 선택한다. (예: 한식)
4. "검색" 버튼을 클릭한다.
5. 로딩 인디케이터가 표시된다.
6. API 응답을 받아 식당 목록이 카드 형태로 렌더링된다. 각 카드에는 식당명, 주소, 분류, "OO 시티투어 코스 주변" 배지가 표시된다.
7. 결과가 없으면 "조건에 맞는 시티투어 맛집이 없습니다" 안내 문구를 표시한다.
8. (선택) "더보기" 클릭 시 다음 페이지 결과를 추가로 불러온다.

## 4. 화면 구성 (UI Requirements)

### 4.1 검색 영역 (상단 고정)
| 요소 | 설명 |
|---|---|
| 지역 선택 | Select box, 필수. 시/도만 지원할지 시/군/구까지 지원할지는 5.5 참고 |
| 음식 카테고리 선택 | Select box 또는 버튼 그룹, 필수 |
| 검색 버튼 | 두 조건 모두 선택 시 활성화 |

### 4.2 결과 영역
- 카드 리스트 형태
  - 제목: `rstrNm`(+ `rstrBhfNm` 지점명이 있으면 병기)
  - 카테고리 뱃지: `rstrClNm`
  - 주소: `rstrRoadAddr` (없으면 `rstrLnbrAddr` 대체 표시)
  - 보조 배지: "🚌 {title} 코스 주변" (연계 시티투어명)
  - 정보 기준일: `rstrInfoStdDt` (작은 글씨로 하단 표시)
- 총 검색 결과 건수(`totalCount`) 표시
- 모바일 반응형 레이아웃 (1열), 데스크탑 (2~3열 그리드)

### 4.3 상태 처리
- 초기 상태: "지역과 음식 종류를 선택해주세요" 안내
- 로딩 중: 스켈레톤 UI 또는 스피너
- 에러: "일시적인 오류가 발생했습니다. 다시 시도해주세요" + 재시도 버튼
- 결과 없음: "이 지역엔 등록된 시티투어 주변 맛집 정보가 없어요. 다른 지역을 선택해보세요" 안내

## 5. API 연동 설계 (Swagger 확정 스펙)

### 5.1 엔드포인트
```
GET https://api.kcisa.kr/openapi/API_CNV_063/request
```

### 5.2 요청 파라미터 (확정)
| 파라미터 | 설명 | 필수 | 비고 |
|---|---|---|---|
| `serviceKey` | 서비스 인증키 | Y | 활용신청 후 발급 |
| `numOfRows` | 세션당 요청 레코드 수 | Y | 기본값 "10" |
| `pageNo` | 페이지 번호 | Y | 기본값 "1" |
| `areaNm` | 시/도명 또는 시/군구명 (2자 이상) | Y | 예: "서울", "전라남도", "강남구", "순천시" — **단일 텍스트 파라미터** |
| `clNm` | 식당 분류명 | Y | **고정 8종만 지원**: 한식 / 분식 / 치킨 / 동양식 / 서양식 / 패스트푸드 / 뷔페 / 퓨전 |

요청 예시:
```
https://api.kcisa.kr/openapi/API_CNV_063/request?serviceKey={서비스키}&numOfRows=10&pageNo=1&areaNm=서울&clNm=한식
```

### 5.3 응답 구조 (확정)
```
response
├─ header
│   ├─ resultCode
│   └─ resultMsg
└─ body
    ├─ numOfRows
    ├─ pageNo
    ├─ totalCount
    └─ items.item[]   ← 아래 필드를 가진 배열
```

| 필드명 | 설명 | UI 활용 |
|---|---|---|
| `rstrNm` | 식당명 | ✅ 카드 제목 |
| `rstrBhfNm` | 식당 지점명 | ✅ 제목 보조 |
| `rstrAsstnNm` | 식당 보조명 | 필요시 표시 |
| `rstrClNm` | 식당 분류명 | ✅ 카테고리 뱃지 |
| `rstrRoadAddr` | 도로명 주소 | ✅ 주소 |
| `rstrLnbrAddr` | 지번 주소 | 도로명 없을 때 대체 |
| `rstrPnu` | 지번 고유코드 | 내부 식별용 |
| `rstrLatPos` / `rstrLotPos` | 위도 / 경도 | 지도 연동(향후) |
| `rstrGidCd` | 격자코드 | 내부용 |
| `rstrInfoStdDt` | 식당 정보 업데이트일 | "정보 기준일" 표시 |
| `title` | 연계 시티투어명 | ✅ "OO 코스 주변" 배지 |
| `description` / `subDescription` | 시티투어 운행정보 | (선택) 상세 섹션 |
| `spatial` | 시티투어 담당 시군구 | 검색 지역과 다를 수 있음(참고용) |
| `reference` | 시티투어 문의처 | (선택) |
| `source` | 시티투어 홈페이지 | (선택) 외부 링크 |
| `rights` | 지자체 담당부서 | 사용 안 함 |
| `dataOfferInst` / `dataStdDt` | 제공기관 / 데이터 기준일 | 하단 출처 표기용 |

> **전화번호(tel) 필드는 제공되지 않음** — 4.2의 카드 UI에서 전화번호 항목 제외.

### 5.4 인증키 보호
서비스키는 **프론트엔드에 노출되면 안 되므로, 백엔드(BFF) 또는 서버리스 함수를 경유하여 호출**해야 함 (6장 참고).

### 5.5 지역 입력 방식
- `areaNm`은 시/도·시/군구를 구분하지 않는 **단일 텍스트 파라미터**이므로 계층형 코드 매핑이 불필요합니다.
- 프론트 UX는 두 가지 방식 중 선택:
  - **(A) 단순화(MVP 권장)**: 시/도 드롭다운만 제공, `areaNm`에 시/도명 그대로 전달
  - **(B) 세분화**: 시/도 → 시/군/구 계층 드롭다운을 유지하되, 최종 선택된 시/군/구명만 `areaNm`으로 전달 (예: "강남구"). 이 경우 시/도-시/군구 매핑 데이터는 행정표준코드 등 공개 코드표를 프론트에 정적으로 내장 (별도 지역코드 조회 API 불필요)
- `clNm`은 코드가 아닌 8개 한글 문자열이므로 프론트에 버튼/드롭다운으로 하드코딩 가능.
- ⚠️ `areaNm`이 정확히 일치(exact match)해야 하는지, 부분 포함(like) 검색인지는 문서에 명시되어 있지 않으므로 서비스키 발급 후 "서울"과 "서울특별시" 등으로 실제 테스트 호출을 해서 검증 필요.

## 6. 기술 아키텍처 (제안)

```
[사용자 브라우저]
     │  (지역/카테고리 선택, 검색)
     ▼
[프론트엔드: React/Next.js]
     │  fetch("/api/restaurants?areaNm=..&clNm=..&pageNo=..")
     ▼
[백엔드/BFF: Next.js API Route 또는 별도 서버]
     │  serviceKey 포함하여 api.kcisa.kr 호출
     │  (선택) 응답 캐싱 - 동일 조건 재요청 시 API 호출 절약
     ▼
[api.kcisa.kr/openapi/API_CNV_063/request]
```

- **서비스키 보호**: 반드시 서버 사이드에서 API를 호출하고, 클라이언트에는 정제된 JSON만 반환
- **캐싱**: 동일 (areaNm, clNm, pageNo) 조합 결과를 일정 시간(예: 1일) 캐싱하여 API 호출 수 절약 및 응답 속도 개선. 시티투어 연계 데이터 특성상 갱신 빈도가 낮을 가능성이 높아 캐싱 효율이 좋을 것으로 예상
- **에러/레이트리밋 대응**: API 트래픽 제한 초과 시 사용자에게 안내 및 재시도 로직

## 9. 오픈 이슈 / 확인 필요 사항 (Open Questions)
1. `areaNm`이 정확 일치인지 부분 검색(like)인지 — 서울 전체 vs 특정 구 단위 검색 시 결과 차이 검증 필요

5. 데이터 갱신 주기 (`rstrInfoStdDt`, `dataStdDt` 필드로 유추 가능하나 실측 필요)
