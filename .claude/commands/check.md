대상 폴더: `$ARGUMENTS` (비어 있으면 사용자에게 어느 폴더인지 먼저 확인할 것)

대상 폴더 안의 모든 `.html` 파일(하위 폴더 포함, `node_modules`·`.next`·`.vercel` 등 빌드/의존성 산출물은 제외)을 찾아 각각 아래 세 가지를 점검한다.

1. **제목** — `<title>` 태그가 존재하고, 비어있지 않으며, 페이지 내용을 설명하는 제목인지 확인한다.
2. **깨진 링크** — `href`/`src`로 참조하는 로컬 파일(다른 html, css, js, 이미지 등)이 실제로 존재하는지 확인한다. `http(s)://`로 시작하는 외부 링크는 이 점검 대상이 아니다(필요시 별도로 언급만 한다).
3. **콘솔 에러** — 각 html 파일을 브라우저(claude-in-chrome)로 열어 콘솔에 에러가 발생하는지 확인한다. 서버 없이 파일을 직접 열어 확인하되(`file://` 경로), 만약 페이지가 fetch 등으로 인해 파일 프로토콜에서 정상 동작하지 않는다면 `python -m http.server`로 잠깐 띄워서 확인한다.

점검이 끝나면 파일별로 아래와 같은 표로 정리해서 보고한다:

| 파일 | 제목 | 깨진 링크 | 콘솔 에러 | 상태 |
|---|---|---|---|---|
| (경로) | (통과 / 수정 필요 + 사유) | (통과 / 수정 필요 + 목록) | (통과 / 수정 필요 + 내용) | (통과 / 수정 필요) |

표 아래에 "수정 필요"로 표시된 항목이 있다면 각각 무엇을 어떻게 고쳐야 하는지 간단히 덧붙인다. 이 명령은 점검과 보고만 하며, 사용자가 별도로 요청하지 않는 한 파일을 직접 수정하지 않는다.
