## 1. 개요 (Overview)

### 1.1 제품 정의
영수증을 카메라로 촬영하면 AI가 상호명, 날짜, 품목, 금액을 자동으로 인식하여 지출 내역으로 기록하고, 지출을 카테고리별로 자동 분류하여 차트/대시보드 형태로 시각화해주는 **PWA(Progressive Web App) 기반 가계부 서비스**.

### 1.2 배경 및 문제 정의
- 기존 가계부 앱은 수기 입력 의존도가 높아 **입력 피로도**로 인한 중도 이탈률이 높음.
- 카드사/은행 연동 가계부는 정확하지만 **현금 결제, 간이영수증, 다인 정산** 등 커버리지가 낮음.
- 사용자는 "기록"보다 "지출 패턴 파악"에 더 큰 니즈가 있으나, 기존 앱은 입력 단계에서 이탈이 발생해 데이터가 누적되지 않음.

### 1.3 목표 (Goals)
| 구분 | 목표 |
|---|---|
| 사용자 목표 | 영수증 촬영만으로 3초 내 지출 기록 완료 |
| 비즈니스 목표 | 낮은 입력 마찰로 리텐션 및 데이터 누적률 극대화 |
| 제품 목표 | AI 인식 정확도 기반 신뢰도 있는 자동 가계부 구축 |

### 1.4 타겟 사용자
- 20~40대, 지출 관리에 관심 있으나 수기 입력이 귀찮아 가계부 앱을 포기한 경험이 있는 사용자
- 현금·간이영수증 결제가 잦은 자영업자, 학생, 프리랜서
- 모바일 웹 접근성을 선호하며 앱 설치 부담을 줄이고 싶은 사용자 (PWA 특성 활용)

### 1.5 핵심 가치 제안 (Value Proposition)
> "찍기만 하면 끝. 분류는 AI가, 확인은 당신이."

## 2. 성공 지표 (KPI)

| 지표 | 정의 | 목표치 (출시 3개월 기준) |
|---|---|---|
| 영수증 인식 성공률 | OCR+AI 파싱 성공 / 전체 촬영 건수 | 90% 이상 |
| 카테고리 분류 정확도 | 사용자 수정 없이 확정된 분류 비율 | 80% 이상 |
| 촬영→기록 완료 시간(TTV) | 촬영 시작 ~ 저장 완료까지 평균 시간 | 10초 이내 |
| WAU/MAU (Stickiness) | 주간 활성 / 월간 활성 | 40% 이상 |
| D7 리텐션 | 가입 후 7일차 재방문율 | 35% 이상 |
| 영수증 기록 건수 | 사용자당 주간 평균 기록 건수 | 5건 이상 |

## 3. 전체 사용자 플로우 (User Flow)

```
[스플래시] → [온보딩] → (권한 허용: 카메라/알림)
     ↓
[홈 - 하단 탭: 피드 · 트렌드 · (중앙 FAB 촬영) · 대시보드 · 마이]
     ↓ (플로팅 버튼 탭)
[영수증 촬영] → [AI 영수증 분석 (로딩)] → [AI 카테고리 분류 (자동)]
     ↓
[확인 및 수정 화면] → 저장
     ↓
[지출 피드에 반영] ⇄ [대시보드 차트 갱신] ⇄ [트렌드 비교 갱신]
```

하단 탭 구성은 5개 영역(좌측부터 피드 · 트렌드 · 중앙 원형 FAB(촬영) · 대시보드 · 마이)이며, FAB는 탭이 아니라 어느 화면에서든 촬영 오버레이를 여는 진입점이다.

## 4. 화면별 상세 요구사항

### 4.1 스플래시 (Splash Screen)

**목적:** 앱 실행 시 브랜드 노출 및 초기 리소스(인증 토큰, 캐시, PWA manifest) 로딩

| 항목 | 내용 |
|---|---|
| 노출 시간 | 최대 1.5초 (초과 시 스켈레톤 UI로 전환) |
| 로딩 중 처리 | 로그인 세션 확인, 최근 캐시된 지출 데이터 프리페치 |
| 분기 처리 | 신규 사용자 → 온보딩 / 기존 사용자(권한 미허용) → 온보딩 권한 단계 / 기존 사용자(정상) → 홈 |
| PWA 특이사항 | manifest.json의 `theme_color`, `background_color`와 일치하는 네이티브 스플래시 노출 (iOS/Android 홈 화면 추가 시) |

**Acceptance Criteria**
- [ ] 오프라인 상태에서도 스플래시 및 캐시 데이터로 앱 진입 가능
- [ ] 로딩 3초 초과 시 타임아웃 처리 및 재시도 안내

---

### 4.2 온보딩 (Onboarding)

**목적:** 핵심 가치(자동 인식) 체험 유도 및 필수 권한 획득

**구성 (3~4 스텝 캐러셀)**
1. 서비스 소개: "영수증만 찍으면 가계부 완성"
2. 핵심 기능 소개: AI 인식 → 자동 분류 → 대시보드 (움짤/일러스트)
3. 권한 요청: 카메라 권한 (필수), 알림 권한 (선택 - 지출 리마인드용)
4. 회원가입/로그인 or 게스트 모드 진입

**요구사항**
- 온보딩 스킵 가능 (단, 카메라 권한은 촬영 시점에 재요청)
- 소셜 로그인(Google/Apple/Kakao) 및 이메일 가입 지원
- 온보딩 완료 여부는 로컬 스토리지 + 서버 플래그로 이중 저장 (PWA 특성상 캐시 초기화 대응)

**Acceptance Criteria**
- [ ] 권한 거부 시에도 앱 사용 가능하되, 촬영 기능 진입 시 재안내 팝업 노출
- [ ] 온보딩 이탈률 측정을 위한 스텝별 이벤트 로깅

---

### 4.3 영수증 촬영 (Receipt Capture)

**목적:** 빠르고 정확한 영수증 이미지 획득

**기능 요구사항**
| 기능 | 상세 |
|---|---|
| 카메라 접근 | `getUserMedia` API 기반 웹 카메라 스트림 (PWA 환경) |
| 촬영 가이드 | 영수증 경계 인식 가이드라인(오버레이) 표시, 자동 수평 보정 |
| 다중 촬영 | 긴 영수증 대응을 위한 이어찍기(스티칭) 옵션 |
| 갤러리 업로드 | 기촬영 이미지 선택 업로드 지원 (카메라 미지원 환경 대응) |
| 촬영 품질 체크 | 흐림/저조도/잘림 감지 시 재촬영 유도 (촬영 즉시 클라이언트 단 프리체크) |
| 오프라인 대응 | 오프라인 시 로컬에 임시 저장 후 온라인 복귀 시 자동 업로드 (Background Sync API) |

**Acceptance Criteria**
- [ ] 저조도/흐림 감지 시 촬영 전 경고 오버레이 노출
- [ ] 촬영 완료 즉시 로컬 미리보기 표시 → "분석 시작" CTA
- [ ] 카메라 미지원 브라우저에서는 자동으로 파일 업로드 UI로 폴백

---

### 4.4 AI 영수증 분석 (AI Receipt Parsing)

**목적:** 촬영된 이미지에서 구조화된 지출 데이터 추출

**처리 파이프라인**
1. 이미지 전처리 (크롭, 왜곡 보정, 대비 향상)
2. OCR 텍스트 추출
3. LLM/구조화 모델을 통한 필드 매핑
   - 상호명 (Merchant)
   - 거래 일시 (Date/Time)
   - 품목 리스트 (Item name, 수량, 단가)
   - 합계 금액 (Total), 부가세 등
4. 신뢰도 스코어(Confidence Score) 산출 (필드별)

**UX 요구사항**
- 분석 중에는 로딩 애니메이션 + "영수증을 읽는 중이에요" 등 진행 상태 노출 (평균 처리 목표: 3초 이내)
- 5초 초과 시 백그라운드 처리로 전환, 사용자는 다른 화면 이동 가능 (완료 시 알림/뱃지)
- 인식 실패(전체 실패) 시 수동 입력 폼으로 즉시 전환 제공

**Acceptance Criteria**
- [ ] 필드별 신뢰도 60% 미만인 항목은 확인/수정 화면에서 하이라이트 처리
- [ ] 인식 완전 실패율 5% 이하 목표 (실패 시 수동 입력 폭 즉시 노출)
- [ ] 처리 실패/타임아웃 시 원본 이미지는 보존되어 재시도 가능

---

### 4.5 AI 카테고리 분류 (AI Category Classification)

**목적:** 추출된 상호명/품목 기반 지출 카테고리 자동 태깅

**기본 카테고리 (1차, 확장 가능)**
- 식비(외식/카페), 식비(장보기), 교통, 쇼핑, 의료/건강, 문화/여가, 생활/공과금, 교육, 반려동물, 기타

**분류 로직**
- 1순위: 상호명 기반 매칭 (자체 상호명-카테고리 매핑 DB)
- 2순위: 품목 텍스트 기반 LLM 분류
- 3순위: 사용자의 과거 동일 상호 분류 이력 우선 반영 (개인화 학습)

**요구사항**
- 사용자가 수정한 분류는 다음 동일 상호 발생 시 자동 반영 (학습 피드백 루프)
- 카테고리 커스텀 생성/이름 변경/아이콘 지정 가능
- 다중 카테고리 필요 시(예: 대형마트 영수증에 식비+생활용품 혼재) 품목 단위 분리 분류 지원 (v1.1 이후 고도화 항목으로 명시 가능)

**Acceptance Criteria**
- [ ] 신규 상호 최초 발생 시에도 유사 상호 기반 추천 카테고리 제시
- [ ] 사용자 수정 이력이 있는 상호는 재방문 시 100% 해당 카테고리로 자동 적용

### 4.6 확인 및 수정 (Review & Edit)

**목적:** AI 분석 결과에 대한 최종 사용자 검수 및 정정, 데이터 신뢰도 확보

**화면 구성**
- 원본 영수증 이미지 썸네일 (탭 시 확대)
- 편집 가능 필드: 상호명, 날짜, 카테고리(드롭다운/칩 선택), 총 금액, 품목 리스트(개별 수정/삭제/추가), 메모, 결제 수단
- 신뢰도 낮은 필드는 노란색/주황색 등으로 시각적 하이라이트
- 하단 CTA: "저장" / "다시 촬영"

**요구사항**
- 금액 필드는 숫자 키패드 최적화, 실시간 합계 검증 (품목 합 ≠ 총액 시 경고)
- 반복 지출(정기결제 등) 감지 시 "정기 지출로 등록" 제안
- 저장 시 오프라인 상태여도 로컬 저장 후 동기화 큐 등록

**Acceptance Criteria**
- [ ] 모든 필드 수정 후 "저장" 시에만 지출 피드에 반영 (임시 상태 이탈 시 초안 자동 보관)
- [ ] 품목 합계와 총액 불일치 시 저장 전 경고 노출 (강제 차단은 아님)
- [ ] 수정 이력은 AI 카테고리 학습 피드백으로 전송

### 4.7 지출 피드 (Expense Feed)

**목적:** 시간 순 지출 내역을 직관적으로 탐색

**구성 요소**
- 일자별 그룹핑된 리스트 (오늘/어제/최근 순)
- 각 항목: 카테고리 아이콘, 상호명, 금액, 결제수단 뱃지
- 일별/주별 소계 표시
- 필터: 기간, 카테고리, 금액 범위, 결제 수단
- 검색: 상호명/품목/메모 텍스트 검색
- 항목 탭 시 상세 화면(원본 영수증 이미지 포함) 이동, 스와이프로 빠른 수정/삭제

**Acceptance Criteria**
- [ ] 무한 스크롤 + 가상화(virtualized list)로 대량 데이터에서도 부드러운 스크롤 유지
- [ ] 오프라인 상태에서도 로컬 캐시된 피드 조회 가능
- [ ] 삭제는 되돌리기(Undo) 스낵바 제공 후 확정 삭제

### 4.8 대시보드 (Dashboard)

**목적:** 누적된 지출 데이터를 시각화하여 소비 패턴 인사이트 제공

**구성 요소**
| 위젯 | 설명 |
|---|---|
| 이번 달 총 지출 요약 | 전월 대비 증감률(%) 표시 |
| 카테고리별 도넛/파이 차트 | 탭 시 해당 카테고리 지출 피드로 드릴다운 |
| 월별 추이 라인/바 차트 | 최근 6개월 지출 트렌드 |
| Top 지출처 랭킹 | 상호명 기준 지출 top 5 |
| 예산 대비 진행률 | 카테고리별 예산 설정 시 진행 바(%) 표시 |
| AI 인사이트 카드 | "이번 달 카페 지출이 지난달 대비 20% 증가했어요" 등 자연어 요약 |

**요구사항**
- 기간 선택(주/월/년/커스텀) 전환 가능
- 차트 데이터는 로컬 캐시 우선 렌더링 후 최신 데이터로 갱신 (Stale-While-Revalidate)
- 예산 초과 임박 시 푸시 알림 연동 (선택 권한 기반)

**Acceptance Criteria**
- [ ] 차트 렌더링 초기 로딩 1초 이내 (캐시 기반)
- [ ] 카테고리 클릭 시 지출 피드로 정확히 필터링되어 이동
- [ ] 데이터 0건(신규 유저)일 때 빈 상태(Empty State) 및 촬영 유도 CTA 노출

### 4.9 트렌드 (Trend)

> 디자인 핸드오프(`project/가계부 앱.dc.html`)에는 하단 탭 4번째 항목으로 구현되어 있었으나 v1.0 초안 작성 시 누락되었던 화면. 실 구현체 반영을 위해 v1.1에서 추가.

**목적:** "내 지출"을 다른 사용자들의 (익명화·집계된) 지출 패턴과 비교해, 소비 습관에 대한 감각을 제공. 4.8 대시보드가 "나의 과거 대비 현재"를 보여준다면, 트렌드는 "나 대 전체 사용자"를 보여준다.

**구성 요소**
| 위젯 | 설명 |
|---|---|
| 또래 평균과 비교 | 카테고리별로 "내 지출 vs 전체 사용자 평균 지출"을 막대 그래프로 비교, "또래 평균보다 N% 더/적게 써요" 라벨 표시 |
| 이번 주 인기 소비 카테고리 · 전체 사용자 | 전체 사용자 기준 이번 주 카테고리별 지출 비중(%) 막대 리스트 |

**요구사항**
- 비교 대상 데이터는 반드시 **집계값(합계·평균·건수)만** 사용하고, 타 사용자의 개별 지출 내역(상호명·금액·시각 등)은 어떤 경로로도 노출하지 않는다 (5.3 보안 및 개인정보 원칙과 동일).
- 집계에 포함된 사용자 수(표본)가 너무 적으면("2인 미만" 등) 비교 자체가 무의미하거나 사실상 익명성이 깨질 수 있으므로, 최소 표본 기준 미달 시 비교 위젯 대신 "아직 비교할 사용자가 충분하지 않아요" 형태의 빈 상태를 노출한다.
- "또래"는 v1에서는 연령/지역 등 세그먼트 없이 **전체 사용자 평균**을 의미한다 (세그먼트별 또래 비교는 향후 로드맵, 8절 참고).
- 카테고리별 색상/아이콘은 4.5 카테고리 분류의 매핑을 그대로 사용해 대시보드/피드와 시각적 일관성을 유지한다.

**Acceptance Criteria**
- [ ] 내 지출이 0건인 카테고리는 "0원"으로 표시하되 비교 막대 자체는 숨기지 않는다 (전체 평균과의 격차를 인지시키는 것이 목적).
- [ ] 집계 API는 개별 사용자 행(row)을 절대 반환하지 않고, 카테고리별 합계·참여 사용자 수만 반환한다.
- [ ] 데이터 0건(신규 유저, 아직 집계 대상 없음)일 때 빈 상태 및 피드/촬영 유도 CTA 노출.

### 4.10 마이 (My / Profile)

**목적:** 계정 정보 확인과 앱 전역 설정(카테고리·예산, 알림, 결제수단, 데이터 내보내기) 진입점 제공.

**구성 요소**
- 프로필 요약: 아바타(이니셜), 이름, 이메일
- 설정 리스트: 카테고리 · 예산 관리(4.5/4.8 예산 설정과 연결) / 알림 설정 / 결제수단 관리 / 데이터 내보내기

**Acceptance Criteria**
- [ ] "카테고리 · 예산 관리" 진입 시 카테고리별 현재 월 예산 목록과 수정 화면으로 이동한다.
- [ ] "데이터 내보내기"는 사용자 본인의 지출 데이터만 내보내며(5.3 개인정보 원칙), 타 사용자 데이터를 포함하지 않는다.

## 5. 비기능 요구사항 (Non-Functional Requirements)

### 5.1 PWA 특성 요구사항
- **설치 가능성:** manifest.json 기반 홈 화면 추가 지원 (Add to Home Screen)
- **오프라인 지원:** Service Worker 기반 오프라인 캐싱 — 최근 지출 피드, 대시보드 데이터, 미전송 영수증 큐
- **백그라운드 동기화:** Background Sync API로 오프라인 중 촬영된 영수증 온라인 복귀 시 자동 업로드
- **푸시 알림:** Web Push API 기반 예산 초과/정기 지출 리마인드 (선택적 권한)
- **반응형:** 모바일 우선(Mobile-first), 태블릿/데스크톱 대응

### 5.2 성능
- 영수증 분석 평균 처리 시간 3초 이내 (95th percentile 5초 이내)
- 앱 최초 진입(FCP) 2초 이내 (3G 환경 기준)

### 5.3 보안 및 개인정보
- 영수증 이미지는 전송 구간 암호화(HTTPS/TLS), 저장 시 암호화 스토리지 사용
- 개인 식별 정보(카드번호 일부 등)가 영수증에 포함될 경우 마스킹 처리
- 사용자 데이터 삭제 요청 시 원본 이미지 및 파싱 데이터 완전 삭제 정책 수립
- 개인정보처리방침 및 AI 분석 목적 고지 동의 절차 (온보딩 내 포함)

### 5.4 접근성
- 명도 대비 WCAG AA 기준 준수
- 스크린 리더 대응 (주요 CTA, 차트 대체 텍스트)

## 7. 기술 스택 제안 (참고용)

| 영역 | 제안 |
|---|---|
| Frontend | React 기반 PWA (Workbox로 Service Worker 관리) |
| 상태관리 | React Query(서버 캐시) + 로컬 상태관리 |
| OCR/AI | OCR 엔진 + LLM 기반 구조화 파싱, 카테고리 분류 모델 |
| Backend | REST/GraphQL API, 비동기 큐(영수증 분석 워커) |
| 저장소 | 객체 스토리지(영수증 원본 이미지), RDB(정형 데이터) |
| 인증 | OAuth 2.0 (소셜 로그인) |

> 본 스택은 예시이며 실제 결정은 엔지니어링 팀 기술 검토 후 확정 필요.

## 8. 향후 로드맵 (Out of Scope for v1, 참고)

- 카드/은행 계좌 연동 자동 수집 (Open Banking)
- 다인 정산/공유 가계부 (가족, 커플, 모임)
- 품목 단위 카테고리 분리 (한 영수증 내 다중 카테고리)
- 예산 추천 AI (소비 패턴 기반 맞춤 예산 제안)
- 웹훅/캘린더 연동 정기 결제 자동 감지 고도화
