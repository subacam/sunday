## 1. 개요 (Overview)

산책하다가 마음에 드는 장면을 카메라로 찍으면, **Gemini Vision**이 감성 캡션과 태그·무드를 자동으로 붙여주고, 촬영 위치가 지도에 핀으로 쌓이는 개인용 동네 탐험 기록 PWA.
기록이 쌓일수록 **대시보드**에서 나의 산책 패턴(태그, 요일별 빈도, 무드 분포)을 시각적으로 돌아볼 수 있다.

> 이번 버전은 **오늘 하루 안에 개발·확인 가능한 구조**로 범위를 최소화했습니다. 소셜(팔로우/공유) 기능은 이번 범위에서 제외했습니다.

### 1.1 한 줄 정의
> 사진 한 장 → AI가 감성을 붙이고, 지도와 대시보드가 나의 산책을 기억한다.

---

## 2. 목표

1. 사진 촬영만으로 캡션·태그·무드·위치가 자동 기록되는 마찰 없는 경험
2. 지도 위에 쌓이는 나만의 발자취 시각화
3. 쌓인 기록을 태그워드클라우드/요일별 그래프/무드 분포로 돌아보는 대시보드 제공
4. **오늘 하루 안에 핵심 플로우(촬영→AI 분석→저장→지도/피드/대시보드 반영)가 눈으로 확인되는 것**이 최우선 목표

## 4. 기술 스택 (제약사항)

| 영역 | 사용 기술 | 비고 |
|---|---|---|
| AI 캡션/태그/무드 분석 | **Gemini Vision API** | 사진 1장 입력 → 캡션, 태그, 무드 JSON 응답 |
| 인증 | **Supabase Auth** | 이메일 또는 소셜 로그인(Google 등 Supabase 지원 범위 내) |
| DB | **Supabase Postgres** | records 테이블 등 |
| 이미지 저장 | **Supabase Storage** | 촬영/업로드 이미지 저장 |
| 프론트엔드 | PWA (프레임워크 자유, 예: React) | manifest + service worker |
| 지도 | 별도 지도 SDK 필요 (Gemini/Supabase 범위 밖) | ⚠️ 아래 "오픈 이슈" 참고 — 지도 표시를 위한 최소 라이브러리는 선택 필요 |

> ⚠️ 참고: "Gemini Vision/Supabase만 사용"이라는 제약과 별개로, **지도 시각화 자체는 Mapbox/Kakao/Naver/Google Maps 등 지도 SDK가 최소 1개는 필요**합니다 (Gemini·Supabase는 지도 기능을 제공하지 않음). 오늘 하루 안에 빠르게 붙이기엔 무료 티어가 넉넉한 **Kakao 지도 API**나 **Mapbox**를 추천드립니다. 이 부분만 예외로 허용해주시면 될 것 같아요.

## 5. 화면 구성 & 유저 플로우

### 5.1 최초 접속 플로우 (한 번만)
1. **스플래시 화면** — 앱 로고/타이틀 노출 (1~2초 또는 로딩 완료까지)
2. **온보딩 2~3장** — 핵심 가치 소개 (예: "① 찍으면 AI가 감성캡션을 붙여줘요 → ② 지도에 발자취가 쌓여요 → ③ 대시보드로 나의 산책을 돌아봐요")
   - **최초 1회만 노출**: Supabase `users` 테이블에 `onboarding_seen` 플래그 저장 (또는 로그인 전이라면 localStorage로 임시 처리 후 로그인 시 서버 값과 동기화)
3. **로그인** (Supabase Auth)

### 5.2 기록 생성 플로우 (핵심 플로우)
1. 하단 탭 또는 FAB 버튼 → **카메라 촬영** 또는 **갤러리에서 사진 업로드** 선택
2. 사진 확보 즉시 **GPS 위치 기록** (Geolocation API)
3. 이미지를 Supabase Storage에 업로드
4. 이미지를 **Gemini Vision API**에 전달 → 캡션, 태그(3~5개), 무드(1개) 응답 수신
   - 응답 대기 중 로딩 상태 표시
5. 결과 확인 화면 — AI 캡션/태그/무드 노출, 필요 시 간단 수정 가능(선택 사항)
6. **저장** 버튼 → Supabase `records` 테이블에 기록 저장 (이미지 URL, 위경도, 캡션, 태그, 무드, 생성시각)
7. 저장 완료 → 피드/지도에 즉시 반영

### 5.3 탐색 플로우
- **피드 탭**: 사진 찍은 산책 기록을 시간순 리스트/카드로 노출 (사진, 캡션, 태그, 무드, 날짜)
- **지도 탭**: 내가 사진 찍은 위치를 지도 위 핀으로 표시, 핀 클릭 시 해당 기록 상세 카드
- **대시보드 탭**:
  - **태그 워드클라우드**: 누적 태그 빈도 기반 시각화
  - **요일별 기록 수 그래프**: 월~일 기준 막대그래프
  - **무드 분포 차트**: 무드 카테고리별 비율 (파이/도넛 차트)

## 6. 기능 요구사항 (오늘 하루 구현 범위 = 전부 P0)

| 기능 | 설명 |
|---|---|
| 스플래시 화면 | 앱 진입 시 로딩/브랜딩 화면 |
| 온보딩 (2~3장) | 최초 접속시에만 노출, 이후 재노출 안 함 |
| 로그인 | Supabase Auth |
| 카메라 촬영 | 기기 카메라로 즉시 촬영 |
| 갤러리 업로드 | 기존 사진 선택 업로드 |
| GPS 위치 기록 | 촬영/업로드 시점의 현재 위치 캡처 |
| AI 감성 캡션 | Gemini Vision — 사진 기반 캡션 생성 |
| AI 태그 + 무드 | Gemini Vision — 태그 3~5개, 무드 1개 생성 |
| 저장 | Supabase DB에 기록 저장 |
| 피드 | 산책 기록 시간순 리스트 |
| 지도 | 촬영 위치 핀 표시 |
| 대시보드 - 태그워드클라우드 | 누적 태그 빈도 시각화 |
| 대시보드 - 요일별 기록 수 그래프 | 요일별 기록 개수 막대그래프 |
| 대시보드 - 무드분포 차트 | 무드 카테고리 비율 차트 |
| PWA | manifest.json + service worker, 홈 화면 설치 지원 |

> 이번 범위에서는 **공개범위 설정, 팔로우/소셜, 오프라인 지원, 유료화**는 포함하지 않습니다 (이전 버전 대비 축소).

## 7. 데이터 모델

```
User (Supabase Auth 기본 테이블 + 확장)
- id, email, onboarding_seen (bool), created_at

Record (기록)
- id
- user_id (FK)
- image_url (Supabase Storage 경로)
- latitude, longitude
- ai_caption (text)
- ai_tags (text[])
- ai_mood (text, enum-like)
- created_at
```

### 무드 카테고리 (제안, 확정 필요)
Gemini Vision이 일관된 값을 반환하도록 **프롬프트에서 무드 후보군을 고정 리스트로 지정**하는 것을 권장합니다.

예시 후보군: `평온` / `설렘` / `활기` / `쓸쓸함` / `그리움` / `행복` / `여유`

→ 이 리스트가 확정되어야 대시보드의 "무드분포 차트"가 일관된 카테고리로 집계됩니다.

---

## 8. Gemini Vision 프롬프트 설계 (초안)

이미지를 입력하고 아래와 같은 **고정 스키마의 JSON**을 응답받도록 프롬프트 설계 필요:

```json
{
  "caption": "한 문장의 감성적인 캡션",
  "tags": ["태그1", "태그2", "태그3"],
  "mood": "평온"
}
```

- `mood`는 위 7번 섹션의 고정 후보군 중 하나만 반환하도록 프롬프트에 명시
- 캡션은 1문장, 과장되지 않은 감성 톤으로 제한 (길이 가이드 필요 — 예: 40자 내외)

## 9. 오늘 하루 구현 순서 (제안)

1. Supabase 프로젝트 세팅 (Auth, DB 테이블, Storage 버킷)
2. 로그인 화면 + 스플래시 + 온보딩(최초 1회 로직) 퍼블리싱
3. 카메라/갤러리 업로드 → Storage 업로드까지 연결
4. GPS 위치 캡처 연결
5. Gemini Vision API 연동 (프롬프트 고정 → JSON 파싱)
6. 저장 로직 (records 테이블 insert)
7. 피드 화면 (records 리스트 조회)
8. 지도 화면 (핀 표시) — 지도 SDK 선정 후 연결
9. 대시보드 3종 (워드클라우드/요일별 그래프/무드분포) — records 집계 쿼리 기반
10. PWA manifest + service worker 설정, 설치 테스트
