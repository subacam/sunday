# PRD — 랜드마크 날씨 사이트 (가칭: World Weather Landmarks)

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.2 (Draft) |
| 작성일 | 2026-08-18 |
| 상태 | 방향 확정 — 지도 기반 UI / 대륙 필터 / 풀 배경 연출 |
| 데이터 소스 | Open-Meteo Forecast API / Geocoding API (API Key 불필요) |

---

## 1. 개요

### 1.1 한 줄 정의
세계 각국의 랜드마크를 골라 그곳의 **현재 날씨와 현지 시간**을 확인하고, 화면 배경이 그 장소의 **날씨 × 시간대**에 따라 실시간으로 바뀌는 웹사이트.

### 1.2 배경 / 문제 정의
일반적인 날씨 앱은 "내 위치의 정보"를 정확하게 전달하는 데 집중한다. 이 서비스는 정확도보다 **"지금 저곳은 어떤 하늘일까"** 라는 감각적 경험을 판다. 랜드마크를 매개로 장소를 상상하게 만들고, 배경 전환으로 그 장소의 분위기를 즉시 전달하는 것이 차별점이다.

### 1.3 목표 (Goals)
| # | 목표 | 측정 지표 |
|---|---|---|
| G1 | 클릭 한 번으로 임의 장소의 날씨/시간 확인 | 첫 랜드마크 선택까지 걸리는 시간 < 10초 |
| G2 | 날씨·시간에 따른 배경 전환의 몰입감 | 세션당 평균 랜드마크 조회 수 ≥ 3개 |
| G3 | 원하는 도시를 빠르게 탐색 | 검색 결과 표시까지 < 1초 (디바운스 제외) |
| G4 | 실패 상황에서도 이탈하지 않음 | 에러 화면에서 재시도 클릭률 ≥ 40% |

### 1.4 비목표 (Non-Goals)
- 정밀 기상 예보 서비스 (레이더, 특보, 기상 경보)
- 회원가입 / 계정 시스템 (v1 기준)
- 상업적 서비스 운영 — Open-Meteo 무료 티어는 비상업적 용도 기준

## 2. 범위

### 2.1 In Scope (v1)
- **인터랙티브 세계지도 + 랜드마크 마커** (선택 UI 확정)
- 랜드마크 상세: 현재 날씨 + 현지 시간 + 시간별/일별 요약
- 날씨 × 시간대 기반 동적 배경 — **파티클 + 번개 포함 풀 연출** (확정)
- 도시 검색 (Geocoding API 연동, 자동완성)
- 필터 — **대륙별만** (확정)
- 리스트 뷰 (전체 랜드마크 카드 목록)
- 로딩 상태, 에러 상태 전면 정의
- 단위 토글 (℃/℉, km/h·m/s)

### 2.2 Out of Scope (v1)
- 날씨/기온/낮밤 기반 필터 → v1.1 검토 (§F-05 참고)
- 즐겨찾기 / 저장 목록 → v1.1 검토 (localStorage 기반)
- 다국어 (한국어만, 단 API `language` 파라미터로 확장 여지 확보)
- 3D 지구본, 지도 팬/줌 커스텀 타일
- 대기질(AQI), 자외선 지수 상세
- 알림, 푸시, 위젯

## 3. 사용자 & 시나리오

### 3.1 타겟 사용자
- **P1. 여행 상상러** — 가보고 싶은 도시의 지금 분위기를 훑어보는 사람
- **P2. 실용 이용자** — 출장·여행을 앞두고 목적지 날씨를 확인하는 사람
- **P3. 원거리 지인이 있는 사람** — 가족/친구가 있는 도시의 시간과 날씨를 확인

### 3.2 핵심 시나리오
1. 진입 → 지도에서 에펠탑 클릭 → 파리의 현재 시각(22:14)과 비 → 배경이 "밤 + 비"로 전환
2. 검색창에 "레이캬비크" 입력 → 자동완성 선택 → 해당 좌표 날씨 표시
3. 리스트 뷰 진입 → 필터 "지금 맑음" + "아시아" → 조건에 맞는 랜드마크만 표시
4. 네트워크 끊김 → 에러 화면 → 재시도 → 정상 복구

## 4. 정보 구조 & 화면 흐름

```
┌─ 홈 (지도 뷰)
│   ├─ 상단: 로고 / 검색창 / 뷰 전환(지도↔리스트) / 단위 토글
│   ├─ 본문: 세계 지도 + 랜드마크 마커
│   └─ 랜드마크 클릭 → 상세 패널 (데스크톱: 사이드 패널 / 모바일: 바텀시트)
│
├─ 리스트 뷰
│   ├─ 필터 바 (대륙 / 날씨 / 기온 / 낮밤 / 정렬)
│   └─ 랜드마크 카드 그리드 (각 카드에 현재 날씨·시간 미니 표시)
│
└─ 상세 뷰 (패널)
    ├─ 랜드마크명 / 도시 / 국가
    ├─ 현지 시간 (실시간 갱신) + 낮/밤 표시
    ├─ 현재 기온, 체감, 날씨 상태, 습도, 풍속, 강수
    ├─ 시간별 예보 (24h 가로 스크롤)
    ├─ 일별 예보 (7일)
    └─ 데이터 출처 표기 (Open-Meteo 링크 — 필수)
```

전역 배경 레이어는 모든 화면 뒤에 존재하며, 선택된 랜드마크 상태에 따라 변경된다. 선택 전 기본값은 사용자 로컬 시간 기준 배경.

## 5. 기능 요구사항

### F-01. 랜드마크 지도 / 선택
| 항목 | 내용 |
|---|---|
| 설명 | **인터랙티브 세계지도** 위 랜드마크 마커를 클릭해 해당 지점의 날씨를 조회 (메인 진입 화면) |
| 우선순위 | P0 |
| 지도 구현 | SVG 벡터 지도 (TopoJSON 기반, 타일 서버 미사용). 배경 연출을 해치지 않도록 **국경선만 있는 미니멀 스타일** — 지형·라벨 없음. 지도 색상은 배경 상태에 따라 명도만 조정 |
| 인터랙션 | - 팬(드래그) / 줌 (휠·핀치·버튼, 1x~4x)<br>- 더블클릭 줌인, "전체 보기" 리셋 버튼<br>- 대륙 필터 선택 시 해당 대륙으로 자동 줌·센터 이동 (600ms 이징) |
| 마커 | - 초기 랜드마크 30~40개 (대륙별 최소 4개 균형 배치)<br>- 마커 = 날씨 아이콘 + 기온 뱃지. 줌 레벨 낮으면 아이콘만, 높으면 랜드마크명까지<br>- hover: 확대 + 툴팁 / 선택: 펄스 링 강조<br>- 밀집 지역(서유럽·동아시아)은 줌 2x 미만에서 클러스터링, 클러스터 클릭 시 해당 영역 줌인 |
| 선택 시 | 상세 패널 오픈 + 배경 전환 + URL 갱신 (`/?l=eiffel-tower`) + 마커가 패널에 가리지 않도록 지도 오프셋 이동 |
| 키보드 | Tab으로 마커 순회(대륙→랜드마크 순), Enter 선택, 방향키로 지도 팬 |
| 인수 조건 | 마커 클릭 후 500ms 내 로딩 스켈레톤 표시, 데이터 도착 시 배경 크로스페이드 완료. 지도 팬/줌 중 60fps 유지 |

> **모바일**: 지도가 기본 뷰이되 세로 화면에서는 초기 줌을 사용자 지역 중심으로 잡고, 상세는 바텀시트로 띄운다. 지도 조작이 어려운 환경을 위해 리스트 뷰 토글을 항상 노출한다.

### F-02. 랜드마크 상세 (날씨 + 시간)
| 항목 | 내용 |
|---|---|
| 우선순위 | P0 |
| 표시 항목 | **현지 시간**(HH:mm, 1초 단위 갱신), 날짜/요일, 현재 기온, 체감온도, 날씨 텍스트, 습도, 풍속·풍향, 강수확률, 일출·일몰 |
| 시간 계산 | API 응답의 `utc_offset_seconds`를 기준으로 클라이언트에서 계산 (서버 시간 의존 금지). `timezone=auto` 사용 |
| 예보 | 시간별 24h, 일별 7일 |
| 인수 조건 | 표시된 현지 시간이 실제 해당 타임존 시간과 ±2초 이내 일치 |

### F-03. 동적 배경 (핵심 차별점)
| 항목 | 내용 |
|---|---|
| 우선순위 | P0 |
| 입력값 | ① 시간대 구분 (일출/일몰 대비 현재 시각) ② 날씨 그룹 (WMO 코드 → §8 매핑) |
| 출력 | 그라디언트 배경 + **canvas 파티클 레이어**(비·눈·안개) + **번개 플래시** + 구름 레이어 + 랜드마크 실루엣 |
| 전환 | 랜드마크 변경 시 그라디언트 800ms 크로스페이드, 파티클은 기존 것 400ms 페이드아웃 후 신규 400ms 페이드인 (겹침 금지 — 비와 눈이 동시에 보이지 않도록) |
| 성능 | 파티클은 단일 `<canvas>` + `requestAnimationFrame`. 상세 예산은 §9.4 |
| 접근성 | `prefers-reduced-motion: reduce` 시 파티클·번개 전면 비활성, 그라디언트만 적용 (필수) |
| 안전장치 | 번개 플래시는 광과민성 발작 위험이 있으므로 §9.4의 빈도·명도 제한을 반드시 준수하고, 설정에서 "배경 효과 끄기" 토글을 제공 |
| 상세 규칙 | §9 배경 매트릭스 |

### F-04. 도시 검색창
| 항목 | 내용 |
|---|---|
| 우선순위 | P0 |
| 동작 | 2자 이상 입력 시 검색 (Open-Meteo Geocoding 규칙: 1자 이하는 결과 없음), 300ms 디바운스 |
| 결과 | 최대 8건. `도시명 · 행정구역 · 국가` 형식으로 표시, 동명 도시 구분 |
| 선택 시 | 해당 좌표로 날씨 조회 → 상세 패널 오픈 (랜드마크가 아니어도 동일 UI) |
| 키보드 | ↑↓ 이동, Enter 선택, Esc 닫기 |
| 예외 | 결과 0건 시 "검색 결과가 없습니다" + 오타 가능성 안내. 이전 요청은 취소(AbortController) |

### F-05. 필터
| 항목 | 내용 |
|---|---|
| 우선순위 | P1 |
| 필터 축 | **대륙 단일 축** — 전체 / 아시아 / 유럽 / 북미 / 남미 / 아프리카 / 오세아니아 |
| 선택 방식 | 다중 선택 가능한 칩(chip) 바. 아무것도 선택하지 않으면 "전체"와 동일 |
| 적용 범위 | **지도와 리스트에 동시 적용**. 지도에서는 비해당 마커를 제거하는 대신 30% 불투명도로 흐리게 처리(맥락 유지), 리스트에서는 완전히 제외 |
| 지도 연동 | 단일 대륙 선택 시 해당 대륙 바운딩 박스로 자동 줌. 다중 선택 시 전체 뷰 유지 |
| 정렬 | 리스트 뷰에서만 — 이름순(기본) / 기온 높은순 / 기온 낮은순 / 현지 시간순 |
| 동작 | 랜드마크 JSON의 `continent` 필드만 사용하는 **순수 클라이언트 필터링**. API 호출 없음 |
| UX | 상태를 URL에 반영 (`/?c=asia,europe`) — 공유·새로고침 시 유지. "전체 해제" 버튼 |
| 인수 조건 | 필터 변경 시 100ms 내 지도·리스트 동시 갱신 |

> **v1.1 후보**: 날씨 상태 / 기온 구간 / 낮·밤 필터. 이 축들은 전체 랜드마크의 실시간 날씨가 있어야 동작하므로, §7.1 일괄 조회 결과를 그대로 재사용하면 API 변경 없이 추가 가능하다. v1에서는 자료 구조만 이를 수용하도록 설계한다.

### F-07. 로딩 화면
| 항목 | 내용 |
|---|---|
| 우선순위 | P0 |
| 유형 | ① **초기 진입 로딩** — 풀스크린. 로고 + 진행 인디케이터. 지도 데이터 + 랜드마크 일괄 날씨 조회 완료까지<br>② **부분 로딩** — 상세 패널/카드 스켈레톤 UI<br>③ **인라인 로딩** — 검색창 우측 스피너 |
| 규칙 | - 최소 표시 시간 400ms (깜빡임 방지), 최대 대기 10초 후 타임아웃 → 에러 화면<br>- 스켈레톤은 실제 레이아웃과 동일한 크기로 (CLS 방지)<br>- 로딩 중에도 이전 배경 유지 (흰 화면 금지) |

### F-08. 에러 화면
| 항목 | 내용 |
|---|---|
| 우선순위 | P0 |
| 케이스 | §10 에러 매트릭스 참조 |
| 구성 | 일러스트 + 무엇이 잘못됐는지(한 줄) + 사용자가 할 수 있는 행동(재시도 버튼 / 홈으로) |
| 원칙 | 기술 용어·에러코드 노출 금지 (단, 접힘 영역에 상세 코드는 개발용으로 유지). 재시도는 지수 백오프 최대 3회 |

### F-09. 단위 설정
- ℃ ↔ ℉, m/s ↔ km/h ↔ mph 토글. localStorage 저장.
- API 요청 시 `temperature_unit`, `wind_speed_unit` 파라미터로 처리하거나 클라이언트 변환.

## 6. 데이터 모델

랜드마크는 정적 JSON으로 관리 (별도 DB 없음).

```json
{
  "id": "eiffel-tower",
  "name": "에펠탑",
  "nameEn": "Eiffel Tower",
  "city": "파리",
  "country": "프랑스",
  "countryCode": "FR",
  "continent": "europe",
  "latitude": 48.8584,
  "longitude": 2.2945,
  "silhouette": "/assets/silhouettes/eiffel.svg",
  "thumbnail": "/assets/thumbs/eiffel.webp",
  "description": "1889년 만국박람회를 위해 세워진 파리의 상징"
}
```

런타임 상태 객체:

```ts
type WeatherState = {
  landmarkId: string;
  temperature: number;      // ℃
  apparentTemperature: number;
  weatherCode: number;      // WMO
  weatherGroup: WeatherGroup; // 'clear' | 'cloudy' | ...
  isDay: 0 | 1;
  humidity: number;
  windSpeed: number;
  utcOffsetSeconds: number;
  sunrise: string;          // ISO, 현지시간
  sunset: string;
  fetchedAt: number;        // epoch ms — 캐시 판단용
};
```

## 7. API 연동 명세

### 7.1 현재 날씨 + 예보
```
GET https://api.open-meteo.com/v1/forecast
  ?latitude=48.8584
  &longitude=2.2945
  &current=temperature_2m,apparent_temperature,relative_humidity_2m,
           weather_code,wind_speed_10m,wind_direction_10m,is_day,precipitation
  &hourly=temperature_2m,weather_code,precipitation_probability
  &daily=weather_code,temperature_2m_max,temperature_2m_min,sunrise,sunset
  &timezone=auto
  &forecast_days=7
```
- 응답의 `utc_offset_seconds`, `timezone`으로 현지 시간 계산
- **다중 좌표 일괄 조회 지원**: `latitude=48.85,35.65,40.68&longitude=2.29,139.83,-74.04` 형태로 콤마 구분 → 랜드마크 전체를 1회 요청으로 처리
- 일괄 조회는 **지도 마커의 날씨 아이콘·기온 뱃지**와 리스트 카드에 사용된다. 마커용으로는 `current` 파라미터만 요청해 응답 크기를 줄이고, 상세 패널을 열 때 해당 좌표만 `hourly`·`daily` 포함해 재요청한다
- 초기 진입 시 일괄 조회가 지연되면 마커를 중립 스타일(회색 점)로 먼저 렌더하고, 데이터 도착 시 아이콘으로 교체한다 — 지도 자체는 API를 기다리지 않는다

### 7.2 도시 검색 (Geocoding)
```
GET https://geocoding-api.open-meteo.com/v1/search
  ?name=서울&count=8&language=ko&format=json
```
- 응답: `results[].{id, name, latitude, longitude, country, admin1, timezone, population}`
- `results` 필드가 아예 없을 수 있음 → 0건 처리 필수
- 2자 미만은 요청하지 않음 (API 규칙상 결과 없음)

### 7.3 캐싱 / 호출 정책
| 항목 | 정책 |
|---|---|
| 날씨 캐시 TTL | 10분 (동일 좌표 재요청 시 캐시 사용) |
| 검색 캐시 | 동일 쿼리 문자열 5분 |
| 요청 취소 | 검색·랜드마크 전환 시 이전 요청 AbortController로 취소 |
| Rate limit | 무료 티어 기준 일 10,000회 수준. 일괄 조회로 호출 수 최소화 |
| 실패 처리 | 429/5xx → 지수 백오프 재시도 (1s → 2s → 4s), 3회 실패 시 에러 화면 |

### 7.4 라이선스 / 표기 (필수)
Open-Meteo는 비상업적 사용 시 무료이며 **출처 표기 의무**가 있다. 푸터와 상세 패널 하단에 "Weather data by Open-Meteo.com" 링크를 반드시 노출한다.

## 9. 배경 전환 매트릭스

### 9.1 시간대 구분 (일출·일몰 기준 상대 계산)
| 구간 | 조건 |
|---|---|
| `dawn` (새벽/여명) | 일출 −60분 ~ 일출 +30분 |
| `day` (낮) | 일출 +30분 ~ 일몰 −60분 |
| `dusk` (노을) | 일몰 −60분 ~ 일몰 +30분 |
| `night` (밤) | 그 외 |

### 9.2 배경 조합
| 시간대 × 날씨 | 그라디언트 | 오버레이 |
|---|---|---|
| day + clear | 청량한 하늘색 → 흰빛 | 태양 글로우, 렌즈 플레어 |
| day + cloudy/overcast | 회청색 → 밝은 회색 | 느리게 흐르는 구름 |
| day + rain | 짙은 회색 → 청회색 | 빗줄기 파티클, 유리 물방울 |
| day + snow | 창백한 회백색 | 눈송이 파티클 (느린 낙하) |
| day + fog | 뿌연 베이지-그레이 | 블러 레이어 + 낮은 대비 |
| day + thunderstorm | 어두운 남회색 | 빗줄기 + 간헐적 번개 플래시 |
| dawn / dusk + clear | 주황–분홍–보라 그라디언트 | 낮은 태양, 긴 그림자 |
| dawn / dusk + 강수 | 탁한 자주–회색 | 강수 파티클 + 낮은 채도 |
| night + clear | 남색 → 검정 | 별, 달 |
| night + cloudy | 짙은 회남색 | 어두운 구름, 별 일부 가림 |
| night + rain/snow | 거의 검정 → 남색 | 파티클 + 도시광 반사 |
| night + thunderstorm | 검정 | 번개 플래시 (강도 높음) |

### 9.3 공통 규칙
- 랜드마크 실루엣은 전경에 고정, 배경 색상에 따라 실루엣 명도만 조정
- 텍스트 가독성 확보를 위해 배경 위 반투명 스크림(scrim) 레이어 항상 유지 — 대비비 4.5:1 이상
- `prefers-reduced-motion: reduce` 시 파티클·플래시 비활성, 그라디언트만 적용

### 9.4 파티클 · 번개 명세 (풀 연출)

**레이어 구조** (아래 → 위)
```
1. 그라디언트 배경 (CSS, GPU 합성)
2. 구름 레이어 (SVG/PNG 2~3장, 서로 다른 속도로 수평 이동 — 시차 효과)
3. 파티클 canvas (비/눈/안개 입자)
4. 랜드마크 실루엣
5. 번개 플래시 오버레이 (전체 화면, mix-blend-mode: screen)
6. 스크림 + UI
```

**파티클 파라미터**

| 날씨 | 입자 수 (데스크톱) | 낙하 속도 | 각도 | 형태 |
|---|---|---|---|---|
| 이슬비 | 120 | 느림 | 5° | 짧은 선, 낮은 불투명도 |
| 비 (약~강) | 200 / 350 / 500 | 보통~빠름 | 10~18° (풍속 연동) | 선 (길이 8~20px) |
| 소나기 | 400 | 빠름 | 15° | 선 + 간헐적 밀도 변화 |
| 눈 | 150 / 250 / 350 | 매우 느림 | 좌우 흔들림(sin) | 원형, 크기 3단계 |
| 안개 | — | — | — | 파티클 대신 블러 + 반투명 레이어 2장 수평 이동 |
| 뇌우 | 500 (비) | 빠름 | 20° | 선 + 번개 |

- 풍속(`wind_speed_10m`)을 낙하 각도에, 풍향(`wind_direction_10m`)을 좌우 방향에 매핑 → 데이터가 연출에 반영되는 지점
- 입자는 화면 밖으로 나가면 상단에서 재활용 (object pooling, GC 최소화)

**번개 플래시 규칙 (안전 기준 포함)**
- 발생 간격: 8~20초 사이 랜덤 (WMO 96/99는 5~12초로 단축)
- 1회 플래시 = 60ms 밝기 상승 → 120ms 감쇠, 최대 2연속(더블 플래시)까지
- **최대 불투명도 0.35를 넘지 않는다** — 화면 전체가 흰색으로 번쩍이지 않도록
- **초당 3회 이상 깜빡임 금지** (WCAG 2.3.1 광과민성 발작 기준)
- 탭이 백그라운드일 때(`visibilitychange`) 애니메이션 전면 중단

**성능 가드**
| 조건 | 처리 |
|---|---|
| 모바일 (viewport < 768px) | 입자 수 50%로 감소 |
| `devicePixelRatio > 2` | canvas 해상도 상한 2x로 제한 |
| FPS 45 미만 3초 지속 | 입자 수 자동 50% 감소 (1회만), 그래도 미달 시 파티클 중단 후 정적 배경 |
| 배터리 절약 모드 감지 시 | 파티클 비활성 |
| 탭 비활성 | rAF 루프 정지 |

## 10. 에러 매트릭스

| 케이스 | 트리거 | 화면/문구 | 액션 |
|---|---|---|---|
| E-01 네트워크 오프라인 | `navigator.onLine === false` 또는 fetch 실패 | "인터넷 연결을 확인해 주세요" | 재시도 / 온라인 복귀 시 자동 재조회 |
| E-02 API 타임아웃 | 10초 초과 | "날씨 정보를 불러오지 못했어요" | 재시도 |
| E-03 API 5xx | 서버 오류 | "날씨 서버에 문제가 있어요. 잠시 후 다시 시도해 주세요" | 재시도 (백오프) |
| E-04 API 429 | 요청 한도 초과 | "요청이 많아요. 잠시 후 다시 시도해 주세요" | 60초 후 자동 재시도 |
| E-05 잘못된 파라미터 (400) | 좌표 오류 등 | "위치 정보를 처리할 수 없어요" | 홈으로 |
| E-06 검색 결과 없음 | `results` 없음/빈 배열 | "'{쿼리}'에 대한 검색 결과가 없습니다" | 검색어 수정 유도 (에러 화면 아닌 인라인 빈 상태) |
| E-07 필터 결과 0건 | 필터 조합 불일치 | "조건에 맞는 랜드마크가 없어요" | "필터 초기화" 버튼 |
| E-08 잘못된 URL 랜드마크 ID | `?l=unknown` | 404 상태 — "존재하지 않는 랜드마크예요" | 홈으로 |
| E-09 부분 실패 | 일괄 조회 중 일부 좌표 실패 | 해당 카드만 "정보 없음" 표시 | 카드 단위 재시도 |
| E-10 예상치 못한 런타임 오류 | ErrorBoundary | "예기치 못한 문제가 발생했어요" | 새로고침 |

**원칙**: 전체 화면 에러는 E-01~E-05, E-08, E-10에만 적용. 그 외는 인라인/부분 처리로 컨텍스트를 잃지 않게 한다.

1. **랜드마크 시각 자산** — 실루엣 SVG를 랜드마크마다 제작할지, 사진/일러스트로 대체할지. 30개 기준 실루엣 자체 제작은 디자인 리소스가 별도로 필요하다. (배경 연출을 풀로 가는 만큼 사진보다 실루엣이 어울리지만, 비용이 가장 큰 항목)
2. **랜드마크 최종 리스트** — 30개 내외 가정. 대륙별 배분과 후보 선정 필요.
3. **SSR 필요 여부** — 공유 링크 미리보기(OG 이미지에 현재 날씨 반영 등)를 노린다면 Next.js, 아니면 Vite SPA로 충분.
4. **지도 국경 표현** — 분쟁 지역 경계 표기는 데이터셋(world-atlas) 기본값을 그대로 쓸지, 별도 검토할지. 서비스 성격상 기본값 사용이 무난하나 사전 인지 필요.
5. **배경 효과 기본값** — 저사양 기기 첫 방문 시 파티클을 기본 ON으로 둘지, 감지 후 자동 OFF로 시작할지.
