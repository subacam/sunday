| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-08-18 |
| 상태 | 초안 |

## 1. 개요

### 1.1 프로젝트 목적
네이버 뉴스 검색 API(`https://naverapihub.apigw.ntruss.com/search/v1/news`, NAVER API HUB / NCP API Gateway)를 활용하여, 사용자가 키워드로 최신 뉴스를 검색하고 정렬·탐색할 수 있는 웹 서비스를 제작한다. (2026-07-31부로 developers.naver.com 검색 오픈API 신규 발급이 종료되고 NCP API Gateway 방식으로 이전됨.)

### 1.2 핵심 가치
- 빠르고 직관적인 뉴스 검색 경험 제공
- 인기 키워드를 통한 즉각적인 탐색 유도
- 모바일/데스크톱 어디서든 끊김 없는 반응형 UI
- API 키 등 민감 정보의 완전한 서버 사이드 보호

### 1.3 타깃 사용자
- 특정 이슈나 키워드에 대한 최신 뉴스를 빠르게 확인하고 싶은 일반 사용자
- 여러 언론사의 기사를 한 화면에서 비교하고 싶은 사용자

## 2. 범위 (Scope)

### 2.1 포함 (In Scope)
- 키워드 검색 (검색창)
- 인기 키워드 칩 (클릭 시 즉시 검색)
- 기사 카드 리스트 (제목, 요약, 언론사/날짜, 링크)
- 정렬 기능: 최신순 / 정확도순
- 로딩 상태 화면
- 검색 결과 없음 화면
- 에러 화면 (API 실패, 네트워크 오류 등)
- 반응형 레이아웃 (모바일 / 태블릿 / 데스크톱)
- API 키 보안 (.env.local + 서버 프록시)

### 2.2 제외 (Out of Scope) — v1 기준
- 회원가입/로그인, 개인화 추천
- 뉴스 스크랩/북마크 저장 (서버 DB 필요, 추후 확장)
- 다국어 지원
- 댓글/공유 기능

## 3. 기술 스택 (제안)

| 영역 | 기술 |
|---|---|
| 프레임워크 | Next.js (App Router) |
| 언어 | TypeScript |
| 스타일링 | Tailwind CSS |
| 상태 관리 | React useState / useSWR 또는 TanStack Query (캐싱, 재요청 관리) |
| API 통신 | Next.js Route Handler(API Route)를 통한 서버 프록시 |
| 배포 | Vercel |

> Next.js를 제안하는 이유: 클라이언트에서 네이버 API를 직접 호출하면 CORS 오류가 발생하고 키가 노출되므로, 반드시 서버(API Route)를 경유해야 함.

## 4. 보안 요구사항 (API 키 보호) — 최우선 순위

### 4.1 원칙
네이버 API 키(`Client ID`, `Client Secret`)는 **절대 클라이언트(브라우저) 코드나 깃허브 저장소에 노출되어서는 안 된다.**

### 4.2 구현 방식

1. **`.env.local` 사용**
   - 프로젝트 루트에 `.env.local` 파일 생성
   - 아래와 같이 키 저장:
     ```
     X-NCP-APIGW-API-KEY-ID=발급받은_ID
     X-NCP-APIGW-API-KEY=발급받은_SECRET
     ```
   - **`NEXT_PUBLIC_` 접두사를 붙이지 않는다.** (붙이면 브라우저에 번들되어 노출됨)

2. **`.gitignore` 등록**
   - `.env`, `.env.local`, `.env.*.local` 을 `.gitignore`에 등록하여 커밋 자체를 차단 (제공된 `.gitignore` 파일 참고)
   - 커밋 전 `git status`로 `.env.local`이 목록에 없는지 항상 확인

3. **서버 프록시 아키텍처**
   - 브라우저 → 우리 서버(`/api/news`) → 네이버 API 순서로만 통신
   - 브라우저는 네이버 API 주소나 키를 절대 알 수 없음
   ```
   [클라이언트] --검색어--> [/api/news (서버)] --Client-ID/Secret 헤더--> [네이버 뉴스 API]
   [클라이언트] <--가공된 JSON 결과-- [/api/news (서버)] <--원본 응답-- [네이버 뉴스 API]
   ```

4. **배포 환경 변수 분리**
   - Vercel 등 배포 플랫폼의 "Environment Variables" 설정 화면에 동일한 키를 별도 등록
   - 로컬(.env.local)과 배포 환경 변수는 완전히 분리되어 관리됨

5. **키 노출 시 대응**
   - 실수로 커밋된 이력이 있다면 즉시 네이버 개발자센터에서 키를 재발급(rotate)

## 5. 기능 요구사항

### 5.1 검색창 (Search Bar)
- 화면 상단 고정, 텍스트 입력 필드 + 검색 버튼(또는 Enter 키)
- 입력값 공백만 있을 경우 검색 비활성화
- 최근 검색어 없이 v1은 단순 텍스트 검색만 지원 (자동완성 제외)
- 검색 실행 시 URL 쿼리 파라미터(`?q=검색어&sort=sim`)에 상태 반영 → 새로고침/공유 시에도 결과 유지

**수용 기준**
- [ ] 검색어 입력 후 Enter 또는 버튼 클릭 시 결과 갱신
- [ ] 빈 값 검색 시 아무 동작 안 함 (또는 안내 메시지)

### 5.2 인기 키워드 칩 (Popular Keyword Chips)
- 검색창 하단에 5~8개의 추천/인기 키워드를 칩(Pill) 형태로 노출
- v1: 미리 정의된 고정 키워드 리스트(예: "속보", "경제", "AI", "스포츠" 등) — 실시간 급상승어 API는 별도 계약 필요하므로 제외
- 칩 클릭 시 해당 키워드로 즉시 검색 실행 및 검색창에 반영

**수용 기준**
- [ ] 칩 클릭 시 검색창 텍스트와 결과가 동시에 갱신됨
- [ ] 현재 선택된(마지막 검색된) 키워드는 시각적으로 강조(active 상태)

### 5.3 기사 카드 리스트 (Article Card List)
각 카드에 포함되는 정보:
- 기사 제목 (HTML 태그 제거, `<b>` 강조 태그는 하이라이트로 변환 가능)
- 기사 요약(description)
- 언론사명 또는 출처 도메인
- 발행일시 (상대 시간 표기 권장: "3시간 전")
- 클릭 시 새 탭에서 원문 기사로 이동 (`target="_blank" rel="noopener noreferrer"`)
- 리스트는 그리드(데스크톱 2~3열) / 1열(모바일) 레이아웃

**수용 기준**
- [ ] 카드 클릭(또는 제목 클릭) 시 원문 새 탭 오픈
- [ ] 제목에 포함된 `<b>` 등 HTML 태그가 깨지지 않고 정상 렌더링됨
- [ ] 무한 스크롤 또는 페이지네이션으로 추가 결과 로드 (택 1, 권장: 페이지네이션 또는 "더보기" 버튼)

### 5.4 정렬 기능 (Sort)
- 옵션: **정확도순(sim)** / **최신순(date)** — 네이버 뉴스 API의 `sort` 파라미터 그대로 매핑
- 드롭다운 또는 토글 버튼 형태, 검색창 근처 또는 결과 리스트 상단에 배치
- 정렬 변경 시 현재 검색어 기준으로 즉시 재검색

**수용 기준**
- [ ] 정렬 변경 시 스크롤 위치가 리스트 상단으로 이동
- [ ] 정렬 상태가 URL 쿼리에 반영되어 새로고침해도 유지

### 5.5 로딩 화면 (Loading State)
- 검색 요청 중에는 스켈레톤 카드(Skeleton UI) 또는 스피너 표시
- 기존 결과가 있는 상태에서 재검색 시에도 로딩 인디케이터 노출 (레이아웃 급변 방지)

**수용 기준**
- [ ] 300ms 이상 응답 지연 시 로딩 UI 노출 (너무 빠른 응답에는 깜빡임 방지를 위해 지연 적용 고려)
- [ ] 로딩 중 검색 버튼/입력 비활성화 또는 중복 요청 방지

### 5.6 결과 없음 화면 (Empty State)
- 검색 결과가 0건일 때: 일러스트 또는 아이콘 + "'{검색어}'에 대한 검색 결과가 없습니다" 메시지
- 다른 검색어 제안 또는 인기 키워드 칩 재노출

**수용 기준**
- [ ] 결과 0건 응답 시 에러 화면이 아닌 별도의 Empty State가 노출됨
- [ ] 검색어가 결과 없음 메시지에 정확히 표시됨

### 5.7 에러 화면 (Error State)
발생 가능 케이스:
- 네이버 API 서버 오류 (5xx)
- 인증 실패 (401/403 — 키 오류)
- 요청 한도 초과 (429)
- 네트워크 연결 끊김 (클라이언트)

UI:
- 명확한 에러 메시지 + "다시 시도" 버튼
- 사용자에게는 기술적 에러 코드 대신 친화적 문구 노출 (콘솔/서버 로그에는 상세 에러 기록)

**수용 기준**
- [ ] API 실패 시 앱 전체가 크래시되지 않고 에러 화면만 표시
- [ ] "다시 시도" 클릭 시 동일 조건으로 재요청

### 5.8 반응형 디자인 (Responsive)
| 브레이크포인트 | 레이아웃 |
|---|---|
| 모바일 (~639px) | 검색창 풀 너비, 카드 1열, 칩 가로 스크롤 |
| 태블릿 (640~1023px) | 카드 2열 |
| 데스크톱 (1024px~) | 카드 3열, 최대 콘텐츠 너비 제한(예: 1200px) 후 중앙 정렬 |

**수용 기준**
- [ ] 모바일에서 가로 스크롤(원치 않는 overflow) 없음
- [ ] 터치 타깃(버튼, 칩) 최소 44x44px 확보

## 7. API 연동 명세

### 7.1 서버 라우트 설계 (`/api/news`)

| 항목 | 내용 |
|---|---|
| Method | GET |
| Query Params | `query` (검색어, 필수), `sort` (`sim`\|`date`, 기본값 `sim`), `page` 또는 `start` (페이지네이션) |
| 내부 동작 | 서버에서 `process.env['X-NCP-APIGW-API-KEY-ID']`/`process.env['X-NCP-APIGW-API-KEY']`를 헤더에 담아 네이버 API 호출 → 응답 가공 후 클라이언트에 반환 |
| 응답 예시 | `{ items: [...], total, currentPage }` |

### 7.2 네이버 뉴스 API 매핑
| 우리 서비스 파라미터 | 네이버 API 파라미터 |
|---|---|
| 검색어 | `query` |
| 정확도순 | `sort=sim` |
| 최신순 | `sort=date` |
| 페이지 | `start`, `display` (최대 100건/요청) |

### 7.3 에러 코드 매핑 (서버 → 클라이언트)
| 네이버 응답 | 클라이언트 처리 |
|---|---|
| 200 + items 0건 | Empty State |
| 401/403 | 에러 화면 ("서비스 일시 오류") — 상세 원인은 서버 로그로만 |
| 429 | 에러 화면 ("잠시 후 다시 시도해주세요") |
| 5xx / 타임아웃 | 에러 화면 + 재시도 버튼 |

## 8. 비기능 요구사항

- **성능**: 검색 응답 목표 1.5초 이내 (네이버 API 응답 시간에 종속)
- **접근성**: 시맨틱 HTML, 이미지/아이콘 alt 텍스트, 키보드만으로 검색 가능
- **SEO**: 검색 결과 페이지에 대한 메타 태그 동적 설정 (선택)
- **캐싱**: 동일 검색어+정렬 조합에 대해 짧은 시간(예: 60초) 서버 캐싱 고려 → API 호출량 절감
