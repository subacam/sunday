# PRD: 가게 길찾기

## 1. 개요

### 1.1 배경 및 문제 정의
기존 지도/맛집 서비스(네이버맵, 카카오맵, 망고플레이트 등)는 가게의 주소는 제공하지만, 실제 건물 내 정확한 위치(출입구가 앞쪽인지 뒤쪽인지, 몇 층인지, 어느 골목으로 들어가야 하는지 등)는 알기 어렵다. 사용자는 주소만 보고는 건물에 도착해도 실제 입구를 찾지 못해 헤매는 경우가 많다.

### 1.2 타겟 사용자
- 낯선 동네에서 약속 장소를 찾는 사람
- 골목 상권/복합건물 밀집 지역을 방문하는 사람
- 초행길인 관광객

### 1.3 핵심 가치 제안
"주소는 아는데 입구를 못 찾는" 문제를 해결한다. 사용자들이 직접 남긴 사진, 설명, 정밀 핀 위치를 통해 누구나 헤매지 않고 가게 입구까지 도달할 수 있도록 돕는다.

### 1.4 서비스명
가칭 **"가게 길찾기"**

### 1.5 서비스 한 문장 정의
**낯선 동네에서 약속 장소나 가게를 찾는 사람이(누가), 주소만으로는 정확한 입구를 찾기 어려울 때(언제), 헤매지 않고 바로 도착하기 위해(왜)** 사용하는, 사용자들이 직접 남긴 사진·설명·정밀 핀으로 가게의 진짜 위치를 알려주는 서비스.

## 2. 목표 및 성공 지표

### 2.1 MVP 목표
1개월 내 빠르게 출시하여 핵심 가설(정확한 위치 정보가 사용자에게 실질적 가치를 주는가)을 검증한다.

### 2.2 핵심 성공 지표
- **재방문율 / 활성 사용자 수 (MAU/WAU)**: 사용자가 이 서비스의 가치를 실제로 느끼고 지속적으로 재방문하는지를 핵심 지표로 삼는다.

### 2.3 참고 지표 (2순위)
- 가게 등록 수
- 위치 정보 완성률 (등록된 가게 중 위치 정보가 채워진 비율)
- 위치 정보 "도움이 됐어요" 수
- 길찾기 버튼 클릭 수

## 3. 오늘의 작업 범위: 랜딩페이지

> **오늘 실제로 만드는 것은 랜딩페이지 1개뿐이다.** 4장에 정리한 "핵심 기능"은 서비스가 궁극적으로 제공할 기능 목록이며, 실제 개발은 아직 시작하지 않는다. 오늘의 목표는 이 서비스의 가치 제안을 검증하기 위한 **랜딩페이지를 통해 반응(가입 의사, 대기자 등록 등)을 모으는 것**이다. 랜딩페이지 구성안은 8장을 참고.

## 4. 로드맵 — 서비스 핵심 기능 (오늘 개발 대상 아님)

> 아래는 "가게 길찾기"가 앞으로 단계적으로 제공할 기능이다. 오늘은 이 중 어떤 것도 실제로 개발하지 않으며, 랜딩페이지를 통해 반응을 모은 뒤 우선순위에 따라 착수한다.

### 4.1 향후 MVP 핵심 기능 목록
| 기능 | 설명 |
|---|---|
| 가게 등록 | 네이버/카카오 로컬 API 연동으로 기본 정보 자동 입력, 사용자가 직접 등록 가능 |
| 위치 정보 보완 | 사진 + 텍스트 설명 + 지도 핀을 자유롭게 추가 (자유 등록형, 중복 허용) |
| "도움이 됐어요" | 각 위치 정보에 대해 유용함 카운트만 제공 (정렬/랭킹 로직 없음) |
| 검색/탐색 | 가게 이름, 지역/동네명, 음식 카테고리, 현재 위치 기반 "내 주변" 검색 |
| 길찾기 연동 | 외부 지도 앱(네이버맵/카카오맵) 딥링크 연결 |
| 로그인 | 소셜 로그인(카카오, 네이버, 구글 등) |

### 4.2 그 다음 단계 (MVP 이후 로드맵)
- 리뷰/평점 작성 기능 (텍스트/사진 리뷰)
- 자체 턴바이턴 내비게이션 (외부 지도 앱 딥링크로 대체)
- 지도 기반 탐색 UI (리스트/키워드 검색으로 대체)
- 위치 정보 투표/검증 및 정렬 로직 (단순 카운트만 제공)
- 업주 직접 가입 및 가게 관리 권한 시스템

## 5. 상세 기능 명세 (로드맵 기준 — 오늘 개발 대상 아님)

### 5.1 가게 등록
- **등록 주체**: 일반 사용자 누구나 (업주 가입 불필요)
- **기본 정보**: 네이버/카카오 로컬 API 연동을 통해 가게 이름, 주소, 카테고리, 영업시간, 전화번호 등을 자동으로 가져옴 (검색 후 선택)
- **위치 정보(사진/설명/핀)**: 등록 시점에는 **선택 사항**. 기본 정보만으로 가게 등록이 가능하며, 위치 정보는 비어있는 상태로 시작해 이후 다른 사용자가 채워 넣을 수 있음
- **권한**: 로그인 필요

### 5.2 위치 정보 보완/검증
- **방식**: 자유 등록형 — 한 가게에 대해 여러 사용자가 각자 사진/설명/핀을 추가할 수 있으며, 모두 누적되어 표시됨 (기존 정보를 덮어쓰지 않음)
- **입력 요소**:
  - 사진 (건물 외관, 입구, 간판 등)
  - 텍스트 설명 (예: "1층 스타벅스 뒤편 골목, 편의점 옆 계단으로 진입")
  - 지도 위 정밀 핀 위치
- **"도움이 됐어요"**: 각 위치 정보 항목에 대해 사용자가 유용함을 표시할 수 있고, 카운트가 누적됨 (정렬/순위 로직은 MVP 범위 아님)
- **권한**: 로그인 필요

### 5.3 검색/탐색
- **형태**: 리스트/키워드 검색 (지도 기반 탐색 UI는 제외)
- **검색 기준**:
  1. 가게 이름
  2. 지역/동네명 (예: "홍대", "강남역")
  3. 음식 카테고리 (예: "한식", "일식", "카페")
  4. 현재 위치 기반 "내 주변"
- **권한**: 비로그인 사용자도 자유롭게 조회 가능

### 5.4 길찾기 연동
- **방식**: 정확한 핀 좌표를 네이버맵/카카오맵 등 외부 지도 앱으로 전달하는 딥링크 연결
- **범위**: 실제 경로 안내(내비게이션)는 외부 지도 앱에 위임. 자체 내비게이션 기능은 구현하지 않음

### 5.5 로그인/인증
- **방식**: 소셜 로그인만 지원 (카카오, 네이버, 구글 등)
- **적용 범위**:
  - 조회(검색, 가게 상세, 위치 정보 열람): 비로그인도 가능
  - 등록/추가 행위(가게 등록, 위치 정보 추가, 도움이 됐어요): 로그인 필요

## 6. 사용자 시나리오 (예시, 서비스 완성 이후 기준)

1. 사용자가 친구와 홍대의 한 카페에서 약속을 잡았다.
2. "가게 길찾기"에서 카페 이름 또는 지역명으로 검색한다.
3. 가게 상세 페이지에서 다른 사용자가 남긴 입구 사진과 "1층 정문이 아니라 건물 뒤편 주차장 옆 계단으로 올라가야 함"이라는 설명을 확인한다.
4. "길찾기" 버튼을 눌러 카카오맵으로 연결되고, 정확한 핀 위치까지 안내받는다.
5. 무사히 도착한 후, 본인도 로그인하여 최신 사진을 하나 추가하고 기존 설명에 "도움이 됐어요"를 누른다.

## 8. 랜딩페이지 구성안 (오늘의 실제 작업물)

> 오늘 만드는 것은 이 랜딩페이지 1개다. 목적은 "주소만으로는 못 찾는 문제"와 그 해결 방식("가게 길찾기")이 사람들에게 얼마나 공감/매력적으로 느껴지는지 전달하고 확인하는 것이다. 이번 버전에는 별도의 전환 유도(CTA)는 포함하지 않는다.

> **구현 결과**: `day4/index.html` 단일 파일로 완성했다. 아래 표는 실제로 만든 8개 섹션이며, 각 섹션의 디자인 스펙은 `DESIGN.md` 6장에 있다. 최초 구상(6개 섹션)에 최근 리뷰·서비스 특징 두 개를 더한 구성이다.

| 섹션 | 목적 | 주요 내용 |
|---|---|---|
| **1. 히어로 (Hero)** | 3초 안에 무엇을 해결하는 서비스인지 전달 | 서비스명("가게 길찾기"), 헤드라인("주소는 맞는데, 입구를 못 찾겠다면"), 서브헤드라인, 검색창, 등록 현황 3지표 |
| **2. 문제 공감 (Problem)** | 타겟이 겪는 불편에 공감시키기 | 헤맨 경험 3가지를 인용문으로 제시 (건물을 두 바퀴 돈 경험 / 층을 잘못 알아 지각한 경험 / 핀과 실제 입구가 다른 경험) |
| **3. 해결 방식 = 길찾기 (Solution)** | 이 서비스가 어떻게 다른지 보여주기 | 가게 5곳의 입구 정보 카드(가로 스크롤) + "사진 → 설명 → 정확한 핀" 3단계 설명. 모두 예시 데이터 |
| **4. 작동 방식 (How it works)** | 사용 흐름을 간단히 이해시키기 | ① 가게를 검색합니다 → ② 입구를 확인합니다 → ③ 바로 출발합니다 |
| **5. 최근 리뷰** | 서비스가 "살아있다"는 인상을 줌 | 별점 + 한 줄 리뷰가 느리게 흐르는 티커. 예시 데이터이며 리뷰 작성 기능은 제공하지 않음(4.2절) |
| **6. 신뢰/차별점 (Why us)** | 기존 지도 서비스와 다른 이유 | "지도 앱은 건물까지, 가게 길찾기는 문 앞까지" — 지도 앱과 알 수 있는 정보를 좌우로 비교 |
| **7. 서비스 특징** | 확장 가능성 제시 | AI 요약 · 챗봇 · 대시보드에 "준비 중" 뱃지. 4장 로드맵에 없는 신규 제안이므로 반영 여부는 별도 논의 |
| **8. 푸터 (Footer)** | 최소한의 신뢰 요소 | 만든 사람, GitHub 링크, 프로젝트 허브 링크, 저작권 표기 |

### 8.1 랜딩페이지에서 확인하고 싶은 것 (검증 가설)
- 문제(입구를 못 찾는 불편)에 대한 공감이 실제로 존재하는가 → 체류시간/스크롤 깊이로 간접 확인
- 해결 방식(사진/설명/핀 기반 위치 정보)이 매력적으로 느껴지는가 → 페이지 내 반응(스크롤 완주율, 재방문 등)으로 간접 확인

### 8.2 랜딩페이지 성공 기준 (임시)
- CTA/전환 수집이 없는 만큼, 이번 랜딩페이지는 정량적 전환율보다는 **정성적 반응(공유 시 피드백, 지인 반응)** 확인용에 가깝다. 이후 단계에서 전환 유도가 필요해지면 별도로 논의
